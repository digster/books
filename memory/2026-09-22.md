# 2026-09-22 — Dark mode toggle

Added a light/dark switch to every page's header. It is the site's first
JavaScript, and it is strictly additive, per §2.4 of the brief.

## Design decisions

- **Binary switch, OS as the default.** `role="switch"` button labelled
  "Dark" (accessible name "Dark theme"). Only a *deviation* from the OS is
  saved. Flipping back to match the OS deletes the key, so the page follows
  the OS again. That gives a two-state control a way back to "automatic"
  without a third state.
- **`assets/theme.js`**: a classic, synchronous script in `<head>`. It sets
  `data-theme` to the effective theme before the body is parsed, so there is
  no flash. It isn't a module because Chrome won't run modules from
  `file://`. It never calls `fetch()`.
- **Static markup, `hidden` by default.** CSS reveals the switch as soon as
  `data-theme` exists, so it is there from the first frame, with no pop-in
  and no header shift. Its on/off drawing is keyed to the root attribute, not
  to `aria-checked`.
- **Dark tokens duplicated**, once under the media query (guarded by
  `:not([data-theme="light"])`) and once under `[data-theme="dark"]`. Both are
  wrapped in `:where()` so print's `:root` still wins. The checker keeps the
  two blocks identical.
- Listens for OS changes, `storage` (other tabs), and `pageshow` (bfcache).
  Storage access is guarded; where it throws, a choice lasts for one page.
- Forced-colours rules draw the knob in system colours. Print hides the switch
  and pins `color-scheme: light`.

## Also fixed

- **Skip link contrast in dark mode:** it was `#fff` on the pale dark accent,
  2.03:1. It is now `var(--paper-raised)`: 6.75:1 light, 7.77:1 dark. The bug
  predates this work but became more reachable with the toggle.
- Template prose that said "there is no JavaScript on this site"
  (`part-mechanism.html`), and the no-JS claims in `about.html`.

## Tests

- `tools/check.py`: new `theme` check (script in `<head>`, synchronous and
  classic; one switch in `header.site` with the right attributes; dark blocks
  identical). The `network` check now scans `assets/*.js` for
  fetch/XHR/import()/beacon/sockets. Script `src`s are now link-resolved.
  **Negative test:** 18 mutations in a scratch copy, all caught, each for the
  right reason.
- `tools/test_theme.py`: 20 Playwright tests, run with `uv run` (PEP 723
  inline deps; `playwright==1.56.0` matches the environment's Chromium). **Mutation
  test:** 9 implementation breaks, all caught. Two tests had initially passed
  against broken copies and were rewritten (see LEARNINGS).
- Visual pass: desktop and 360px, both themes, hover and focus. Screenshots
  were deleted afterwards.

## Known trade-off

At 360px on book pages the breadcrumb already fills the line, so the switch
wraps to a second, right-aligned row. It is present from the first frame, so
nothing shifts.
