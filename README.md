# The Understudy

Readthroughs that transmit what a book actually contains — its arguments, its
machinery, its evidence, its cases, its arc — at enough depth and completeness
that reading the pages gives you what reading the book would have given you.

A summary tells you what a book is about. These pages tell you what is *in*
it, which is roughly the difference between a menu and a meal.

The full brief lives in **[CLAUDE.md](CLAUDE.md)** — mission, the five tests,
the three kinds of material, the writing standard, and the definition of done.
Read it before writing any book content.

## Viewing it

There is no build step and no install. Open `index.html` in a browser:

```bash
open index.html
```

`file://` is the strictest surface and is fully supported — every path is
relative and nothing loads from the network. To serve it over HTTP instead:

```bash
python3 -m http.server 8347
```

## Checking it

A zero-dependency structural checker validates the mechanical half of the
definition of done. Standard library only; it never writes anything and is
**not** a build step — the site works with it deleted.

```bash
uv run tools/check.py
```

```bash
python3 tools/check.py -v
```

It checks: `.nojekyll` present · every link relative and resolving · every
in-page anchor existing · nothing loading from the network · exactly one
`<h1>` per page · heading order never skipping a level · an `id` on every
heading · `lang`, charset, viewport, skip link and landmarks · footnote
`ref → note → return` round-trips · all six sections present and non-empty on
part pages · each `data-kind` carrying that kind's required apparatus ·
`meta.json` valid, complete, and consistent with the files beside it.

Run `python3 tools/check.py --only links` to run one check.

What it deliberately does not check is everything that matters most —
whether the particulars are there, whether the trace is arithmetically
correct, whether the voices are separable. Those are the passes in §13 of the
brief, and they are done by reading.

## Layout

```
.nojekyll              stops GitHub Pages skipping _template/
index.html             the shelf, regenerated by hand from the meta.json files
about.html             what these pages are, the five tests, the honest limit
assets/
  style.css            the whole stylesheet: reset, tokens, type, layout, components, print
  fonts/               4 self-hosted variable woff2 + their OFL licences
_template/
  part.html            entry point; the shared skeleton and how to copy it
  part-claim.html      claim variant      — joints, case walk, support ledger
  part-mechanism.html  mechanism variant  — ratchet, trace, cost sheet, figure
  part-terrain.html    terrain variant    — axes, items placed
  book-index.html      orientation, arc, coverage table, parts, still-required
  meta.json            the per-book metadata schema
books/                 one folder per book
tools/check.py         the structural checker (dev only, never served)
```

The templates double as the stylesheet's proving ground — between them they
exercise every component in `style.css`. Their placeholder prose describes
what belongs in each slot, so no book content lives in the bootstrap.

### Two deviations from the brief's stated layout, both deliberate

- **Three part templates instead of one.** The brief asks for a single
  `part.html` holding all three kind variants. Three part titles in one file
  would mean three `<h1>`s, which the same brief forbids — or demoting every
  section heading a level, which would stop the real CSS selectors from being
  exercised. `part.html` is now the entry point; the variants are siblings.
- **`PROMPT.md` is a prompt log**, not a copy of the brief. The brief's
  layout section lists `PROMPT.md` as itself, but the brief is checked in as
  `CLAUDE.md`, so duplicating it would only create drift.

`tools/`, `memory/`, `LEARNINGS.md`, `ARCHITECTURE.md`, and `.claude/` are
development files and are never served as part of the site.

## Adding a book

Follow Task B in the brief (§13). In short:

1. **Establish the book** — real contents, chapter structure, edition, and the
   current standing of its claims. Do not write from vague recall.
2. **Build the coverage plan** — chapter list, dispositions, part boundaries,
   the kind of each part, whether the order changes. *Show this before writing
   any parts.*
3. **Write the book index** — orientation, arc, how to read this one, coverage
   table.
4. **Write the parts in order**, each complete before the next. Build the
   decomposition and the concrete run *first*; they are the spine.
5. **Verify** — every particular confirmed, every trace re-executed, every
   case walk checked against sources outside the book.
6. **Passes** — particulars, separation, perturbation (§13 steps 6–8).
7. **Afterword and glossary.**
8. **Build the pages**, fill `meta.json`, draw figures, regenerate
   `index.html` by hand, cross-link related books both ways.
9. **Run the checker**, then verify in a browser: `file://`, dark mode, 360px,
   keyboard focus, offline, print.

`index.html` is regenerated **by hand** from the `meta.json` files. It is never
generated client-side — that would need `fetch()`, which breaks `file://` and
is forbidden outright.

## Constraints

These are non-negotiable and every change preserves them:

- **Static HTML only**, hand-authored. No server, no runtime, no database.
- **No build step.** No npm, no bundler, no SSG, no Sass, no templating. What
  is committed is what is served.
- **No external runtime dependencies.** No CDN, no Google Fonts, no analytics.
  The site renders fully with the network off.
- **JavaScript optional and additive**, and it may never `fetch()`. The
  bootstrap ships **zero** JavaScript; footnote round-trips and the arrival
  highlight are pure CSS.
- **Relative links only.** The tree works at a domain root, at
  `https://user.github.io/repo/`, and from the local filesystem, unchanged.
- **Accessibility and responsiveness are part of done** — semantic landmarks,
  one `<h1>`, correct heading order, visible keyboard focus,
  `prefers-reduced-motion` respected, comfortable at 360px, body contrast
  ≥ 4.5:1.

## Design

The direction is **two surfaces**, recorded in full in
[about.html](about.html):

> The site's commentary sits below the page surface and the worked runs sit
> above it, so a reader scrolling fast knows who is talking before reading a
> word.

`aside.note` is recessed — set *into* the page, in the site's own typeface.
`.case-walk` and `.trace` are raised — lifted off it, with an indigo rule.
Three typefaces carry the same distinction a second time: **serif for the
book, sans for the site, mono for the machinery.**

The dark theme redefines every ground but preserves their *order*, so the rule
needs no second version. In print — where browsers omit background graphics —
the same distinction is re-encoded as borders.

Colour is authored in OKLCH for a perceptually even ramp and committed as plain
hex, with the OKLCH source in a comment beside each token. Every
foreground/background pair clears WCAG AA 4.5:1 on all three grounds, in both
themes.
