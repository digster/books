# Architecture

The "why" behind the structure. For what the project *is*, read
[README.md](README.md); for the standard the content must meet, read
[CLAUDE.md](CLAUDE.md).

---

## 1 · The central structural decision: kind is a property of the part

Everything about how this site is built follows from one classification, and
it is the thing most likely to be got wrong by someone new to the repo:

> **A book is not a kind. A *part* is a kind.**

Genre is the wrong unit. A single book can argue a claim in one chapter,
explain a mechanism in the next, and lay out a landscape in the third — and
each of those needs *different apparatus* to transmit, not different prose
about the same apparatus. So each part page declares `data-kind` on its
`<article>`, and that attribute determines what its `#read` section must
contain:

| Kind | Decomposition | Concrete run | Accounting | Perturbation test |
|---|---|---|---|---|
| `claim` | `ol.joints` | `.case-walk` | `table.support` | contrast |
| `mechanism` | `ol.ratchet` | `.trace` | `table.costs` + a figure | variation |
| `terrain` | `ol.axes` | `table.placements` | trade-off across axes | placement |

This is enforced mechanically: `tools/check.py` reads `data-kind` and fails the
build if the corresponding markup is absent from `#read`. It is the only
content rule the tooling can check, and it is checked because it is the one
whose violation is invisible while reading — a terrain part with no axes reads
like perfectly good prose right up until a reader is asked to place an item
the book never mentioned, and cannot.

Most parts are mixed. Declare the dominant kind, and satisfy the requirements
of any kind genuinely present.

## 2 · Why there is no build step

The constraint is that what is committed is what is served, and that any
`.html` opened from disk works. That rules out npm, bundlers, static site
generators, Sass, and templating — but the consequences that actually bite are
subtler:

- **`index.html` is regenerated by hand** from the `books/*/meta.json` files
  whenever a book is added. It cannot be generated client-side, because that
  would require `fetch()`, and `fetch()` fails under `file://` — so the one
  obvious "improvement" here would silently break the strictest supported
  surface. `tools/` therefore contains a *checker* and deliberately **no
  generator**: a generator would be a build step wearing a different hat.
- **Colour is authored in OKLCH and committed as hex.** There is no
  preprocessor to compute fallbacks, so the conversion happened once at
  authoring time and the OKLCH source sits in a comment beside each token.
  Change the ramp by recomputing from those comments.
- **Syntax highlighting is hand-applied or absent.** Five span classes
  (`.c .k .s .n .hl`) exist in the stylesheet; there is no highlighter.
- **Figures are hand-authored inline SVG**, and must draw themselves from
  theme tokens via the `.fig-*` classes. A figure with hardcoded fills is
  unreadable in dark mode and nothing in the pipeline could rewrite it,
  because there is no pipeline.

### The bootstrap ships zero JavaScript

Not "minimal" — none. Footnote round-trips, the arrival highlight, and the
skip link are all pure CSS (`:target`, `:focus`). If JS is ever added it may
only enhance, and it may never `fetch()`.

## 3 · The stylesheet contract: two surfaces

`assets/style.css` is one file, ordered `reset → tokens → typography → layout
→ components → print`. Its organising idea is a three-step lightness ramp, and
**the ordering between the three grounds is load-bearing**:

```
--paper-sunk   <   --paper   <   --paper-raised          (in lightness)
aside.note         the book      .case-walk / .trace
the SITE talking   itself        the book's machinery being WORKED
```

Three consequences worth knowing before editing:

1. **Dark mode redefines all three but preserves their order.** That is why
   the design rule needs no second statement for dark mode: recessed is always
   darker than its ground, raised is always lighter. If you change one ground,
   change the others to keep the ordering, or the semantics invert.

2. **Print re-encodes the same distinction as borders.** Browsers omit
   background graphics by default, so on paper all three grounds collapse to
   white. If the note/worked-run distinction lived *only* in the grounds, the
   printed page would lose the most important thing the design does. The print
   block therefore gives notes a full box and worked runs a heavy left bar.
   **Any new component that carries meaning in its background needs a print
   rule that carries the same meaning in ink.**

3. **Typeface carries the distinction redundantly**, so it survives greyscale
   and readers who never consciously notice grounds:
   **serif = the book · sans = the site · mono = the machinery.**
   `#where` and `#carry` are sans because they are scaffolding the *site*
   provides; `#voice` and `#ledger` are serif because they are read
   continuously; `#notes` is sans *and* recessed because it is judgment.

### Width, and the one rule about overflow

There is a single centred column capped at `--measure` (68ch). Blocks that
need more room bleed outward by `--bleed` rather than the column widening, so
the measure never changes as the reader scrolls. `--bleed` is `0` below 60rem.

> **Content that cannot shrink scrolls inside its own box. The page body never
> scrolls sideways.**

Tables live in `.table-wrap` / `.support-wrap` / `.coverage-wrap`; code lives
in `pre`; all four have `overflow-x: auto`. Anything with `white-space:
nowrap` that is *not* inside one of those is a horizontal-scroll bug waiting
at 360px — this happened once already, with a `.val` holding a whole
expression. See [LEARNINGS.md](LEARNINGS.md).

### Figures

Authored at a ~420-unit `viewBox` width and capped at `34rem`, which keeps SVG
label text between ~12px at 360px and ~20px on a desktop. SVG text scales with
the drawing, so a wide `viewBox` produces an illegible figure on a phone and
there is no second drawing to fall back to.

## 4 · Where the served tree ends

Everything under `assets/`, `books/`, `_template/`, plus `index.html`,
`about.html` and `.nojekyll`, is the site. Everything else is development
material that happens to live in the same repo:

| Path | Role |
|---|---|
| `tools/check.py` | structural checker; never runs at serve time |
| `memory/` | dated work summaries |
| `LEARNINGS.md` | accumulated gotchas specific to this codebase |
| `.claude/launch.json` | local preview server config |
| `CLAUDE.md`, `PROMPT.md` | the brief, and the prompt log |

`.nojekyll` matters more than it looks: GitHub Pages runs Jekyll by default,
and Jekyll **skips directories beginning with an underscore** — which would
make `_template/` vanish from a deployed site.

## 5 · Verification

Two layers, and the split is deliberate.

**Mechanical — `tools/check.py`.** Nine checks, standard library only. These
are the failures that are boring to re-verify by hand on every page of every
book, and the class of error hand-checking reliably misses: broken relative
links, dangling anchors, absolute paths, a heading level skipped, a footnote
whose return link points nowhere, a `meta.json` whose counts drifted from the
files beside it.

The checker has its own negative test: break one thing per check in a scratch
copy of the tree and confirm each fires. This is not ceremony — it caught two
real bugs in the checker itself, first a false negative (a substring match
that accepted prose mentioning "joints" as a joint map) and then a false
positive (a regex anchoring error). A green run against a correct tree cannot
distinguish a working checker from a broken one.

**Editorial — by reading.** Everything that actually matters is here, and none
of it is automatable: whether the particulars survived, whether the trace is
arithmetically correct, whether the case walk matches what actually happened,
whether the book's voice and the site's are separable in every sentence. The
brief's §13 steps 5–8 define these passes. The trace in the mechanism template
shipped with a wrong shift on the first attempt and was caught by *executing*
it, not by reading it.

**Browser pass:** `file://`, dark mode, 360px, keyboard focus, offline (zero
external network requests), and print.

## 6 · Content invariants the tooling cannot see

Recorded here because they are the ones that get violated silently:

- **Every chapter appears in the coverage table** with one of four
  dispositions, and anything below `full` states a reason. Silently dropping a
  chapter converts "I read the book" into "I read most of it and don't know
  which part I'm missing."
- **Evaluation lives only in `aside.note`, `#notes`, and the afterword.**
  Inside `#read` the site is transmitting; disagreement there is limited to
  attribution.
- **Nothing is invented.** No fabricated quotes, page numbers, statistics,
  dates, or attributions. A confidently wrong detail is worse than a missing
  one, because the reader will repeat it.
- **Code is reimplemented, never transcribed; figures are hand-authored,
  never traced.** Quotes stay under ~15 words, exact, attributed, and rare.
- **The phrase "several examples" is a defect.** If a book names a person,
  place, year, study, quantity, or case that is doing work, it appears.
